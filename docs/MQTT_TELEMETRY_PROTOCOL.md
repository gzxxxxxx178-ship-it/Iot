# MQTT 遥测字段约定

适用入口：`agri/<deviceId>/data`。JSON 的 `deviceId` 必须与主题设备 ID 一致。

## JSON 类型

| 字段 | 类型 | 缺失时的行为 |
|---|---|---|
| `deviceId` | 与主题一致的设备标识 | 拒收 |
| `temperature`、`humidity` | 有限 JSON 数值 | 拒收 |
| `water` | 有限 JSON 数值，单位 ADC | 保留缺测 null |
| `sendCount`、`rssi` | 32 位 JSON 整数 | 保留缺测 null |
| `linkage` | JSON 布尔值 | 保留缺测 null |
| `uptimeMillis` | 非负 64 位 JSON 整数 | 尝试兼容字段 `timestamp`；两者均缺失时沿用旧协议的 0 |

字段只要显式出现，就必须符合类型约定。显式 `null`、数值字符串、对象、数组、布尔值代替数值、小数代替整数及整数溢出，均拒收整条消息，记录设备 ID 和字段错误原因；不会转换为零值或进入入库、推送及规则评估链路。`uptimeMillis` 存在但无效时，不回退到 `timestamp`。

合法的数字 `0` 与布尔值 `false` 不属于缺测。省略可选字段可以兼容旧设备；不接受用显式 `null` 替代省略。未带运行时长的旧消息中，兼容默认值 0 不能用来证明设备刚启动。

## 类型校验与质量校验

类型正确、有限但超出物理范围的读数，继续保留原值，由 `EspService` 标记质量异常；无效质量记录不进入报警和自动化规则。当前实现的范围包括温度 0–50 ℃、湿度 0–100%、水位 0–1023 ADC、RSSI −120–0 dBm，以及非负发送次数。这些是当前采集设备的数据质量约束，不是农艺阈值，也不将 ADC 换算为毫米。

兼容纯文本协议仍保留设备身份校验；新设备应使用上述 JSON 类型。部署前应使用目标固件载荷验证，不自动烧录或操作真实设备。
